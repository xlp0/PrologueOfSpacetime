# PKC — Personal Knowledge Container

## Insight
PKC is the **workshop / knowledge system / operating environment** that surrounds Prof. Ben Koo's capability-building method. The cleanest sentence: **"The kids generate capability. PKC preserves and compounds it."** PKC is not GitHub, not Kubernetes, not Claude Code, not AI, not the rocket — PKC is the *container for the method*.

Three layers exist simultaneously: (1) **a concept/philosophy** ("how do we structure knowledge, process, and project outputs so capability compounds instead of disappearing?"); (2) **a workflow/method** (define goal → build → record process → keep outputs → make reusable); (3) **a software stack/environment** (GitHub repos, docs, maybe wiki/database/services, deployment stuff, infra pieces). The PKC repo itself looks like a deployment stack for a self-hosted environment: MediaWiki, MariaDB, Matomo, Ansible/Docker-style installation, domain/HTTPS setup.

The architecture distinction that took several rounds to clarify: **GitHub** = where code/docs are stored (a shelf/vault); **PKC** = the bigger workshop/knowledge system/project memory; **Kubernetes** = infra layer that runs services (the plumbing under the workshop); **Claude Code / VS Code / OpenCode / Antigravity** = builder tools humans use inside that world. PKC's role is to **capture, structure, and reuse capability** so one kid project becomes a template, one template becomes a program, one program becomes a platform, one platform can eventually support govtech work.

PKC without the kids = an empty workshop. PKC without compounding = "kid built rocket → next week moves to another project → all that knowledge dies in his head / random chats / scattered files → the organization learns nothing." PKC's job is to stop learning from disappearing.
