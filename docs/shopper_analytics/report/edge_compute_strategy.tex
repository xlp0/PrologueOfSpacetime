\section{The Core Limitation}
\begin{itemize}
    \item \textbf{Goal:} Eliminate 1 Terabyte of continuous video stream bandwidth per store.
    \item \textbf{Constraint:} 100 cameras running the full continuous YOLO + DINOv2 pipeline requires \textbf{$\sim$1,436 FP16 TFLOPS}.
    \item \textbf{Capacity:} A single Jetson Orin Nano provides \textbf{40 INT8 TOPS (17 FP16 TFLOPS)}.
\end{itemize}

\subsection*{Off-Time Optimization Strategy}
Does a retail store need real-time face/gender alignment instantly? \textbf{No.} 
We can queue captured face images locally and process this $\sim$1.16 TFLOPS workload overnight during store "Off-Time" (when 0 TFLOPS are being used for tracking) to maximize edge hardware efficiency without interrupting daytime performance.

\section{Final Architectural Conclusion}
By deploying Jetson edge hardware on-site, we achieve our primary goals:
\begin{enumerate}
    \item \textbf{Bandwidth Reduction:} A single Jetson Orin Nano processes the raw video stream locally to perform Deep SORT tracking, cropping out only the necessary bounding boxes. By transmitting these tiny semantic patches instead of full video streams, bandwidth usage is \textbf{significantly decreased}, easily bypassing the 1 TB/store/month limitation.
    \item \textbf{Compute Efficiency:} We only need one low-power Jetson Orin Nano per store to handle the local tracking and overnight batch workloads. This allows us to safely and cheaply offload the massive YOLO26/DINOv2 continuous detection requirements to the centralized Datacomm CLB Cloud.
\end{enumerate}
